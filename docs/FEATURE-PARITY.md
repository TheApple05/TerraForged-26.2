# Feature parity and usability record

This is an evidence inventory, not a completion claim. The user's current priority is a usable **Minecraft Java 26.2 mod for modpacks generally**, without a preferred old release or preset. Stable terrain, customization, and mod compatibility take priority for the first usable artifact. Classic restoration gaps stay visible and must not be described as complete.

Reference sources are original TerraForged `0.2.x` at `3ada751ac25cd3eecee5d198870a3abb89734f52` and selected ReTerraForged 0.0.6 at `29239f1f164d19dbfcccaca4a8277d64e784207c`. Only the latter is the implementation baseline. The original's newest default branch and the later datagen rewrite are not substituted for classic behavior.

Status meanings:

- **Source present:** an actual implementation exists on the stated path, rather than just a key or empty bootstrap.
- **Compiles:** included in a recorded target compiler run; this does not establish Mixin application or functionality.
- **Packaged runtime verified:** only the specific checks reported against a hashed distributable JAR passed in a non-development installation.
- **Visual approved:** actual reference/target images have been reviewed and accepted; no current item has this status.
- **Missing / inherited TODO:** absent, empty, unwired, or explicitly unfinished in the selected baseline/current implementation.

## Current evidence boundary

The recorded [full compiler check](validation/target-build-2026-11-03-compile.json) compiled its **393-source snapshot** with no source exclusions and a reviewed target access widener. Mixin annotation processing was disabled and the diagnostic packaging guard remained enabled in that snapshot. Later runtime-hook changes require their own build/runtime records.

## Terrain and world generation

- **Continents, landforms, mountain chains, terrain blending — source present; target compilation and scoped custom-world runtime recorded; distribution/visual gates pending.** Original Engine-backed generator stages existed in `chunk/TFChunkGenerator` and `chunk/generator`; selected/current code is under `world/worldgen/cell/heightmap`, `cell/continent`, and `cell/terrain`. The selected snapshot retains combined land/ocean terrain rather than the later experimental unconditional plateau replacement. Exact original Engine availability is discussed in the [classic research](research/classic-biomes.md).
- **River networks, tributaries, lakes, wetlands — source present; target compilation recorded; runtime distribution/continuity gates pending.** Selected/current `cell/rivermap` feeds `Heightmap.apply`. These paths preserve more than vanilla river-biome labels. Connected channels, lake levels, swamp eligibility, and neighboring-chunk behavior need actual target worlds.
- **Hydraulic erosion, smoothing, tile filtering — source present; compilation recorded; full determinism/performance gates pending.** `WorldFilters`, tile generation, and filter classes remain. The [core kernel result](validation/core-reviewed.json) covers mathematical helpers, not this complete pipeline, caches, or chunk seams.
- **Modern caves, aquifers, ores, and world height — intentional modern integration; source present; targeted data checks passed; target-world gates pending.** `PresetNoiseRouterData`, configured carvers, dimension/noise settings, and modern game systems replace 1.16-specific machinery. [Dimension data evidence](validation/dimension-data-2026-11-03.json) explicitly does not generate chunks or prove complete tagged-registry decoding. Changed cave/height behavior prevents an automatic block-for-block 1.16 parity claim.
- **Structure placement/adaptation — source present; compilation recorded; runtime gates pending.** Structure rules, beardifier integration, and settings remain. Require locating/generating representative structures on plains, mountains, coasts, and wetlands; successful registry export alone is insufficient.
- **Shared tile lifecycle and prefetch — migrated source present; runtime stress gates pending.** [Decision 0008](decisions/0008-chunk-lifecycle.md) records prefetch before biomes and completion-based drop after features. Cache completion accounting, retries, exceptional generation, and concurrent consumers still need measured runtime verification.

## Biomes and surfaces

- **Classic 17 custom biome variants — missing / inherited TODO.** Original `ModBiomes.register` actively registered them. Selected/current `RTFBiomeData` and `PresetBiomeData` declare the names but register none; `RTFBiomes.coldMarshland()` returns `null`. Real export evidence contains no custom biome definitions. This is not equivalent to restored variants that happen to use vanilla blocks. Exact IDs, parents, conditions, tags/weights, and proposed modern-compatible restoration are in [classic-biomes.md](research/classic-biomes.md).
- **Modern vanilla biome selection — source present; compilation recorded; coverage gates pending.** Cell climate types are mapped to modern multi-noise temperature/humidity pairs. New vanilla biome availability is intentional, but all climate pairs/biome families are not proven reachable. Preserve modern cave and new overworld biomes when adding classic variants.
- **Classic bryce and stone-forest surfaces — missing as their original implementations.** The original actively appended masked terracotta spires and grass-capped stone columns to their custom variants. Current vanilla surface rules plus strata do not establish those algorithms or masks. Native eroded badlands are an available modern feature, not an authenticated replacement for classic BryceSurface.
- **Classic swamp, desert, forest, and frozen-ocean surface treatments — reference implementations identified; equivalent visual behavior unverified.** Original `SetupFactory.createSurfaceManager` explicitly wired them. Modern vanilla surfaces/features and ported erosion/snow paths may cover parts of their purpose, but the exact classic adaptations have not been demonstrated.
- **DunesSurface and SteppeSurface — original source present but not wired in inspected default setup.** Track as experimental/reference paths, not falsely advertised shipped default features that must already have appeared in every classic world.
- **Strata, slope erosion, natural snow, and smoothing — source present; compilation recorded; in-world/visual gates pending.** Surface rules and feature implementations remain. Verify ore-compatible material tags, slope boundaries, snow behavior, and biome-mod surfaces in actual worlds.

## Vegetation, customization, and spawn

- **Custom tree/templates and feature replacement — source/assets present; compilation and export/helper checks recorded; in-world placement/appearance pending.** `world/worldgen/feature/template`, preset configured/placed features, and biome modifiers survive. The export report's three biome-decorator helper assertions and the [legacy patch comparison](validation/legacy-patch-parity-2026-11-03.json) do not prove tree growth or forest appearance in target chunks.
- **Preset models and built-in legacy presets — source present; default export runtime verified for one preset.** World, cave, climate, terrain, river, filter, structure, and miscellaneous settings exist. The real default preset export produced 1,934 files in the recorded run. All presets, imported old JSON, non-default values, and extreme bounds need separate acceptance.
- **In-game list/editor, live preview, sliders, toggles, import/export, and page navigation — migrated source present; target compilation recorded; actual client gate pending.** [Decision 0007](decisions/0007-client-ui-migration.md) records the extraction API and texture migration. Compilation cannot establish that mouse/key callbacks update generation settings; behavioral defects found during client review must be fixed before usability is claimed.
- **Density adapter arithmetic/codecs/traversal — targeted verified subset.** [Density evidence](validation/density-reviewed.json) exercises two production records against actual target game classes. It does not certify every density node, biome choice, or chunk-generation result.
- **Continent-centered and origin-centered spawn search — implemented runtime hooks; helper tests verified; world spawn outcome pending.** Original 0.2.x used a separate land search; selected ReTerraForged hooks were commented/empty. The current scoped search preserves modern climate refinement. [Decision 0010](decisions/0010-spawn-and-terrablender-hooks.md) and [36-assertion helper evidence](validation/spawn-scope-initial.json) distinguish implementation from actual spawn acceptance.
- **ISLANDS spawn preference — inherited TODO / missing.** Selected/current `SpawnType.ISLANDS.getSearchCenter` returns origin, without island detection or preference. Do not label this as implemented island spawning. The original mod's own spawn handler also treated non-origin options as continent-center searches; the exact Engine spawn semantics remain unauthenticated.
- **External performance-config file parsing — inherited TODO unless superseded by a recorded fix.** The selected `PerformanceConfig.read` returns defaults. A configuration path and UI controls are not evidence that every external option is read or effective.

## Modpack compatibility and release gates

- **Fabric — packaged custom generation and save/reload verified within the cited reports' scope.** Client configuration, broader determinism, and modpack compatibility remain gates before a usable target release.
- **NeoForge — requested alongside Fabric; target implementation/runtime not yet verified.** The user explicitly selected both loaders. Historical Forge source remains a reference, and a Fabric artifact is not installable evidence for NeoForge. Current loader-specific registration, biome modifiers, packaging, and runtime checks must be implemented and recorded separately. Legacy Forge support is not implied.
- **TerraBlender — optional source adapters migrated against the real declared 26.2 dependency; optional runtime not verified.** Gating, complete interfaces, positional uniqueness, and current method signatures are documented in decision 0010. Do not advertise Biomes O' Plenty or other biome-mod support before actual installed tests.
- **Other biome/surface/structure mods, C2ME, ModernFix, Sodium/Iris/Distant Horizons, multiplayer clients — unverified.** Modpack suitability requires testing representative combinations and preserving another mod's biome/feature/surface ownership; no blanket compatibility claim follows from vanilla startup.
- **Original Forge extension/event API and developer search commands — original source identified; target API parity not established.** These are separate compatibility/tooling gaps, not proof that modern terrain must use an old loader API.
- **Performance, visual terrain acceptance, and existing-world continuity — pending.** Benchmark exact fixed workloads; capture seed/config/camera reference images; verify saved worlds and new chunk boundaries. No visual approval exists yet, and no migration of an existing classic world is promised.

The first usable modern build can precede optional classic-variant restoration, as requested. A complete classic revival cannot be claimed while those variants/surfaces and other listed gaps remain missing or unverified.
