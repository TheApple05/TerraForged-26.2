# Feature parity and usability record

This is an evidence inventory, not a completion claim. The user's current priority is a usable **Minecraft Java 26.2 mod for modpacks generally**, without a preferred old release or preset. Stable terrain, customization, and mod compatibility take priority for the first usable artifact. Classic restoration gaps stay visible and must not be described as complete.

Reference sources are original TerraForged `0.2.x` at `3ada751ac25cd3eecee5d198870a3abb89734f52` and selected ReTerraForged 0.0.6 at `29239f1f164d19dbfcccaca4a8277d64e784207c`. Only the latter is the implementation baseline. The original's newest default branch and the later datagen rewrite are not substituted for classic behavior.

Status meanings:

- **Source present:** an actual implementation exists on the stated path, rather than just a key or empty bootstrap.
- **Compiles:** included in a recorded target compiler run; this does not establish Mixin application or functionality.
- **Packaged runtime verified:** only the specific checks reported against a hashed distributable JAR passed in a non-development installation.
- **Visual approved:** actual reference/target images have been reviewed and accepted; no current item has this status.
- **Missing / inherited TODO:** absent, empty, unwired, or explicitly unfinished in the selected baseline/current implementation.

## Terrain and world generation

- **Continents, landforms, mountain chains, terrain blending — source present; target compilation and scoped custom-world runtime recorded; distribution/visual gates pending.** Original Engine-backed generator stages existed in `chunk/TFChunkGenerator` and `chunk/generator`; selected/current code is under `world/worldgen/cell/heightmap`, `cell/continent`, and `cell/terrain`. The selected snapshot retains combined land/ocean terrain rather than the later experimental unconditional plateau replacement. Exact original Engine availability is discussed in the [classic research](research/classic-biomes.md).
- **River networks, tributaries, lakes, wetlands — source present; target compilation recorded; runtime distribution/continuity gates pending.** Selected/current `cell/rivermap` feeds `Heightmap.apply`. These paths preserve more than vanilla river-biome labels. Connected channels, lake levels, swamp eligibility, and neighboring-chunk behavior need actual target worlds.
- **Hydraulic erosion, smoothing, tile filtering — source present; scoped target field determinism verified; full reference/performance gates pending.** `WorldFilters`, tile generation and filter classes remain. The [core kernels](validation/core-reviewed.json) cover helpers. The [production boundary workload](validation/server-stress-summary.md) completes 144 FULL chunks and compares 576 terrain-field/classification/biome observations across request orders, with per-world reloads. It does not prove complete pipeline reference parity or every block seam.
- **Modern caves, aquifers, ores, and world height — intentional modern integration; targeted data/default-world runtime passed; exhaustive coverage pending.** Modern routers, carvers, dimension/noise settings and game systems replace 1.16 machinery. [Dimension data evidence](validation/dimension-data-2026-11-03.json) covers nine configurations; scoped actual default-height chunk generation adds runtime evidence. Cave/aquifer/ore distributions, height extremes and complete tagged-registry behavior need broader checks. Changed modern behavior prevents automatic block-for-block 1.16 parity.
- **Structure placement/adaptation — source present; compilation recorded; runtime gates pending.** Structure rules, beardifier integration, and settings remain. Require locating/generating representative structures on plains, mountains, coasts, and wetlands; successful registry export alone is insufficient.
- **Shared tile lifecycle and prefetch — migrated source and scoped production/stress checks verified.** [Decision 0008](decisions/0008-chunk-lifecycle.md) records prefetch before biomes and completion-based drop after features. [Cache regression](validation/cache-reentry-2026-11-03.json) reproduces the original deadlock and verifies its correction; normal-watchdog generation/reload and the 144-FULL-chunk workload pass. Retries, every exceptional path, long-exploration accounting and sustained performance remain broader gates.

## Biomes and surfaces

- **Classic 17 custom biome variants — missing / inherited TODO.** Original `ModBiomes.register` actively registered them. Selected/current `RTFBiomeData` and `PresetBiomeData` declare the names but register none; `RTFBiomes.coldMarshland()` returns `null`. Real export evidence contains no restored TerraForged classic biome definitions; the BOP biome entries do not fill this gap. This is not equivalent to restored variants that happen to use vanilla blocks. Exact IDs, parents, conditions, tags/weights, and proposed modern-compatible restoration are in [classic-biomes.md](research/classic-biomes.md).
- **Modern vanilla biome selection — source present; compilation recorded; coverage gates pending.** Cell climate types are mapped to modern multi-noise temperature/humidity pairs. New vanilla biome availability is intentional, but all climate pairs/biome families are not proven reachable. Preserve modern cave and new overworld biomes when adding classic variants.
- **Classic bryce and stone-forest surfaces — missing as their original implementations.** The original actively appended masked terracotta spires and grass-capped stone columns to their custom variants. Current vanilla surface rules plus strata do not establish those algorithms or masks. Native eroded badlands are an available modern feature, not an authenticated replacement for classic BryceSurface.
- **Classic swamp, desert, forest, and frozen-ocean surface treatments — reference implementations identified; equivalent visual behavior unverified.** Original `SetupFactory.createSurfaceManager` explicitly wired them. Modern vanilla surfaces/features and ported erosion/snow paths may cover parts of their purpose, but the exact classic adaptations have not been demonstrated.
- **DunesSurface and SteppeSurface — original source present but not wired in inspected default setup.** Track as experimental/reference paths, not falsely advertised shipped default features that must already have appeared in every classic world.
- **Strata, slope erosion, natural snow, and smoothing — source present; compilation recorded; in-world/visual gates pending.** Surface rules and feature implementations remain. Verify ore-compatible material tags, slope boundaries, snow behavior, and biome-mod surfaces in actual worlds.

## Vegetation, customization, and spawn

- **Custom tree/templates and feature replacement — source/assets, helpers and scoped world-decoration paths verified; complete template/appearance coverage pending.** Template assets, configured/placed features and biome modifiers survive. The three biome-decorator helper assertions and [legacy patch comparison](validation/legacy-patch-parity-2026-11-03.json) retain their narrower scopes. Real chunk decoration and client feature-sorter identity checks also pass. Every template family, growth condition and classic forest appearance is not individually accepted.
- **Preset models and built-in legacy presets — one legacy-default export/application path verified on both loaders, with and without the tested content stack.** World, cave, climate, terrain, river, filter, structure and miscellaneous models exist. The initial base export wrote 1,934 files; complete BOP exports write 2,745 Fabric / 2,749 NeoForge files. Actual Done callbacks apply the selected seed/settings and create the custom world. All presets, old JSON imports, non-default values and extremes still need separate acceptance.
- **In-game list/editor, preview and selected slider/export/navigation paths — scoped packaged client checks and immediate-Done guard passed on both loaders; broader controls remain gates.** [Decision 0007](decisions/0007-client-ui-migration.md) records the API migration. Dev11 base/content clients each exercise eight real slider callbacks, finite nonconstant 65,536-cell previews, baseline-digest restoration, Done/export/application, creation/save and absence of TerraForged context in the next world. Four hints/labels fit measured native font/widget widths. Every toggle, page, import and keyboard route is not certified; the immediate post-Done regression/correction is tracked above.
- **Density adapter arithmetic/codecs/traversal — targeted verified subset.** [Density evidence](validation/density-reviewed.json) exercises two production records against actual target game classes. It does not certify every density node, biome choice, or chunk-generation result.
- **Continent-centered and origin-centered spawn search — helper tests and scoped world startup verified; policy coverage pending.** Original 0.2.x used separate land search; selected hooks were commented/empty. Current scoped search preserves modern climate refinement. [Decision 0010](decisions/0010-spawn-and-terrablender-hooks.md) and [36 helper assertions](validation/spawn-scope-initial.json) establish the implementation. Tested worlds start and the client camera validates a real loaded surface, but a dedicated origin/continent-policy acceptance matrix remains pending.
- **ISLANDS spawn preference — inherited TODO / missing.** Selected/current `SpawnType.ISLANDS.getSearchCenter` returns origin, without island detection or preference. Do not label this as implemented island spawning. The original mod's own spawn handler also treated non-origin options as continent-center searches; the exact Engine spawn semantics remain unauthenticated.
- **External performance-config file parsing — inherited TODO unless superseded by a recorded fix.** The selected `PerformanceConfig.read` returns defaults. A configuration path and UI controls are not evidence that every external option is read or effective.

## Modpack compatibility and release gates

- **Fabric — packaged base/content-stack client and dedicated-server paths verified within the cited version-specific scope.** Final dev11 client/server results include the immediate-Done guard; broader controls, full determinism and additional mod combinations remain gates.
- **NeoForge — separate native implementation and packaged base/content-stack client/server paths verified.** Native registries/modifiers, editor registration, custom generation, save/reload and absence of TerraForged context in the next world have actual NeoForge evidence. See [decision 0011](decisions/0011-dual-loader-platform.md) and the linked version-specific results. This does not imply legacy Forge support.
- **TerraBlender and one BOP stack — optional runtime verified on both loaders for the exact pinned dependencies.** Actual sampler/TargetPoint uniqueness, material-rule MapCodec identity, complete own-stack export/consumption, BOP generation and per-loader reload pass. [Decision 0014](decisions/0014-terrablender-material-rule-codec.md) retains the upstream serializer defect/correction; [export10 evidence](validation/modpack-biomesoplenty-dev10.md) and [exact11 generation/reload](validation/modpack-biomesoplenty-dev11.md) record versions and limits. This is one tested stack, not a blanket biome-mod guarantee.
- **Other biome/surface/structure mods beyond the pinned BOP stack, C2ME, ModernFix, Sodium/Iris/Distant Horizons, multiplayer clients — unverified.** Representative additional combinations and another mod's biome/feature/surface ownership need their own checks; vanilla startup or one successful stack is insufficient.
- **Original Forge extension/event API and developer search commands — original source identified; target API parity not established.** These are separate compatibility/tooling gaps, not proof that modern terrain must use an old loader API.
- **Performance, user visual acceptance, full seams and classic-world migration — pending.** Save/reload is verified for the recorded new worlds and actual client screenshots exist. Controlled benchmarks, authenticated reference/target comparisons, complete block seams and long exploration remain separate checks. No user visual approval exists, and classic-world migration is not promised.

The first usable modern build can precede optional classic-variant restoration, as requested. A complete classic revival cannot be claimed while those variants/surfaces and other listed gaps remain missing or unverified.
