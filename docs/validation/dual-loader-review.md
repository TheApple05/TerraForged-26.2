## Checks and supporting evidence

- **Registry lifecycle:** `RTFNeoForge.java:15` attaches native event listeners before common bootstrap. `NeoForgePlatformServices.java:52` registers pre-created custom registries in `NewRegistryEvent`, which expressly supports stored registry instances. Entry registration is queued by registry key and drained only by the matching `RegisterEvent` at line56. Dynamic codecs are registered through `DataPackRegistryEvent.NewRegistry` at line61. Current common call sites use the queued registration operation; there are no common direct `getWritable()` call sites bypassing this lifecycle.
- **Registry ownership and other mods:** `NeoForgePlatformServices.java:111` adds cloners from the complete native `DataPackRegistriesHooks.getDataPackRegistriesWithDimensions()` list. This preserves each registry's registered codec, including native biome/structure modifiers and third-party custom registries. It does not clone the whole native biome-modifier registry with the narrower common TerraForged interface codec. `RegistryPatches.java:26` uses that provider before building the ownership-rebound patch. The unchecked key/serializer boundary is confined to the Neo provider; its own inserted modifier records implement both interfaces.
- **Native biome modification:** Neo Add/Replace operate on `BiomeGenerationSettingsBuilder.getFeatures(step)` mutable lists and apply in `AFTER_EVERYTHING`, matching the inherited Forge phase. `Order.add` creates a fresh list before Add clears/repopulates the destination, so aliasing does not erase the source. Replace retains unlisted holders. Filters compare actual holders from the loaded registry view.
- **Client validation cache:** the exact NeoForge26.2.0.93 patched `ChunkGenerator` uses a native `Lazy` for `featuresPerStep`. Native `ServerLifecycleHooks.runModifiers` applies biome modifiers and then calls every level-stem generator's `refreshFeaturesPerStep()` (published source lines265-267). This invalidates an eagerly validated client sorter after the new builder result is installed. Neo's native path therefore does not require the new Fabric-only flag accessor.
- **Optional TerraBlender:** the dependency is compile-only and declared optional in Neo metadata; early mod detection uses FML's loading list. Common compatibility mixins are gated by the actual mod ID. The inspected Neo TerraBlender26.2-26.2.0.0.2 JAR declares mod version26.2.0.0.2, matching the minimum metadata range. Root's active exact-package TerraBlender runtime checks remain the acceptance gate; this review does not infer compatibility from compilation.
- **Client/server separation and editor:** only the client branch of `RTFNeoForge.java:17` calls `RTFNeoForgeClient.attach`. The latter registers the normal-world editor through the real client-only `RegisterPresetEditorsEvent` (`RTFNeoForgeClient.java:14`). Client-only common mixins remain in the JSON `client` list. Dedicated production boot evidence already exists, but the Neo client/editor flow still needs its own runtime check.
- **Packaging:** Neo source sets include all common sources plus only Neo loader sources/resources; they do not package the Fabric provider or entrypoint. The service descriptor names the Neo provider. The JAR classifier and native metadata distinguish loader artifacts. Historical Forge code is excluded by choosing source roots, while active common features are included.

## Review boundaries

Primary evidence was the exact locally resolved NeoForge26.2.0.93 source JAR and patched Minecraft26.2.0.93 source JAR, the resolved TerraBlender Neo JAR metadata, and current project source. Existing [dedicated production boot](neoforge-dev5-first-boot.json) supports basic class separation only; other agents are running newer package tests.

No new builds or test processes were launched for this review. It does not cover every terrain algorithm, custom preset extreme, cross-loader exported-pack interchange, third-party registry implementation, multiplayer login, or Neo client rendering. A successful cloner design is not evidence that every external mod codec supports every datapack export operation.
